# Нефункциональные требования и стек

## Нефункциональные требования

| ID    | Категория          | Требование                                                                              |
|-------|--------------------|-----------------------------------------------------------------------------------------|
| NFR-1 | Безопасность       | Пароли, токены и ключи в `details` не попадают в журнал (заменяются на `***`)             |
| NFR-2 | Безопасность       | Обычный пользователь видит только свои записи, проверка выполняется в модуле             |
| NFR-3 | Безопасность       | Выгрузка CSV защищена от CSV-инъекций (значения с `=`, `+`, `-`, `@` получают префикс)     |
| NFR-4 | Безопасность       | Формы сайта защищены CSRF-токеном, SQL-запросы параметризованы, символы LIKE экранируются |
| NFR-5 | Производительность | Запись события и выборка страницы журнала быстрее 100 мс при 100 000 записей (индексы)    |
| NFR-6 | Целостность        | Записи нельзя изменить через модуль; очистка доступна только администратору и сама попадает в журнал |
| NFR-7 | Переносимость      | Python 3.9+, ядро модуля использует только стандартную библиотеку                          |
| NFR-8 | Качество кода      | Покрытие тестами не ниже 80 %, код проходит flake8, black, isort                           |
| NFR-9 | Управляемость      | Порог важности (какие события сохранять) задаётся одним параметром `min_level`            |

## Ограничения

- Хранилище SQLite, рассчитано на учебный масштаб.
- Нет автоматической ротации журнала, очистку запускает администратор.
- Журнал защищён на уровне модуля, но не от прямого доступа к файлу базы данных.
- Нет записи в стандартный `logging` Python и в текстовые файлы.
